Anti-Money Laundering Detection System

This project applies network analysis and distributed computing to financial transaction monitoring—combining graph-based fraud detection with real-time streaming data processing.

Goals, Challenges and Approach

My goal is to explore how different model architectures, including graph neural networks (GNNs), tree-based models, multi-layer perceptron, and rule-based models, perform on the problem of detecting transactions which may form part of a money-laundering chain.

A major challenge is the data itself. Real transaction datasets are largely unavailable due to regulations surrounding customer privacy at financial institutions. Thus a sythetic dataset was used, which can only mimic real data to a certain extent. In addition to this, even the smallest dataset with the highest proportion of AML labels was composed of millions of transactions with only a tiny fraction of AML occurrences. There is also the issue of AML transactions taking place across multiple financial institutions, but institutions only having access to their own data, making the path from origination to destination difficult to trace.

Feature engineering from the structure of the transaction graph itself is one of the approaches I took to enrich the data. Features such as betweenness centrality, transaction frequency, pagerank, reciprocity, could be calculated from the graph to provide enriched node information. However, this itself is a challenge as such calculations are resource intensive for large graphs and would need to be frequently re-calculated, either by approximation or other method to keep up with real-time changes.

Models Evaluated

To evaluated different approaches for Anti-Money Laundering (AML) detection, multiple neural network architectures were tested. The objective was to understand the value added by graph relationships, temporal transaction patterns, and transaction-level edge features when identifying suspicious activity.

Current Implementation

I've built a baseline rule-based detection system that serves two purposes: providing immediate functionality for the dashboard and establishing performance benchmarks for the graph neural network (GNN) currently in development. The dashboard displays real-time results from this system as transactions are processed.

Architecture

Transaction streams flow through Azure Event Hubs into Databricks, where each transaction is evaluated against the existing transaction graph stored in Azure Blob Storage. Detection results are written to Azure Cosmos DB, and the dashboard updates via Azure Functions API calls that query the most recent processed transactions.

Note on Detection Rates

Due to the naturally low frequency of money laundering patterns and the conservative nature of the rule-based approach, periods showing zero detections are expected during normal operation. This will improve as the GNN model is integrated.
